# Current state

Where2Go ranks dungeon or raid content by the share of eligible loot matching a character's useful saved preferred items. A character-scoped ownership toggle selects exact-item or usable same-slot exclusion using equipped gear and ordinary bags; saved preferences and the ordinary drop pool remain intact. The recommendation panel also has a session-only source control that cycles All, Dungeons, and Raids, applies across Drop and Voidcore mode switches, resets to All on reload, names the selected source state in the button text, and counts only visible filtered targets in its summary. Direct-drop and Voidcore views remain separate. Korean clients show the Voidcore mode as `공허핵` and use addon-owned koKR display names for dungeon, raid, and boss names in recommendation cards, browser source filters, and source tooltip lines; the content-name table is generated from Battle.net Journal API IDs for the current season and staged for review before copying into `Locale.lua`. Sources track gear rewards only; housing, recipes, mounts, pets, and cosmetic appearance rewards from the Journal are excluded from committed loot tables. Mythic+ direct drops use Hero 3/6, while Voidcore dungeon rewards use the Great Vault-equivalent Myth 1/6 level. Mythic raid direct drops use each boss's 1/6, 2/6, 3/6, or final-boss 9/6 level; Voidcore raid rewards use the equivalent Great Vault level, Myth 6/6 for bosses 1–6 and Myth 9/6 for the final two. The manifest targets Interface `120100` (Midnight Season 2).

The TOC loads 25 Lua modules. The registered Lua suite contains 23 specs, including ownership comparisons, Voidcore reward-rank separation, generated tooltip-link templates, deterministic full-link export helpers, source gear-only checks, and the documentation map check.

The two-window UI redesign passed automated checks and its original live WoW checklist in [UI_REDESIGN_QA.md](UI_REDESIGN_QA.md) was completed and confirmed by the user on 2026-09-11, including Raider.IO-aware recommendation placement, persisted title-bar dragging, carried-gear exclusion in both ownership modes, shared item-row summaries, and the separate Voidcore raid levels. Generated full-link tooltip templates passed targeted live-client QA on 2026-09-12: Gebbo's Bottomless Bag and Boots of the Reckless Wanderer showed Myth 2/6 at item level 321, while Aqirbane Reliquary, Silken Voodoo Drape, and Awoken Dreadfang Cuirass retained their special effects. The separate `BONUS_ROLL_RESULT` behavior for a real Voidcore roll remains unconfirmed; see [TODO.md](../TODO.md).

Entry points: `/where2go` or `/w2g` toggle recommendations; `/where2go browse` opens the browser; `pref`, `compare`, `genspec [reset]`, and maintainer-only `genlinks [reset]` are implemented in `Core/Init.lua`. `genlinks` prewarms tracked IDs and scans full per-encounter EJ item links into an account-wide diagnostic export, distinguishing unresolved full links from absent items and retaining raw links. `tools/data-prep/convert_item_link_bonuses.py` normalizes character-specific fields, preserves Encounter Journal context and modifiers, and stages one template per tracked item. Historical plans/specs under `docs/superpowers/` are context, not the current contract.

The repository agent harness now provides bounded Claude review evidence, content- and baseline-bound completion manifests, required-check and live-QA routing, protected-branch and unrelated-change guards, and explicit selected-file commits. Claude review defaults to a 900-second wall-clock timeout and a USD 3.0 budget; it incrementally records `claude-stream.jsonl` and `claude-stderr.log`, ignores inherited MCP servers, terminates the Windows process tree on timeout, and writes `failure.json` with a machine-readable reason without producing `review.json` on failure. Successful stream results preserve status, model identity, baseline commit, and reviewed file hashes; the final review parser accepts a bare JSON object, one enclosing fence, or explanatory prose ending in one fenced JSON object. Claude timeout, CLI/auth/quota, API, or parser failure requires a separate independent Sol review path, never Claude's fallback-model option. Its authoritative PowerShell runner currently passes. An earlier Claude attempt was quota-blocked and the GPT-5.5 fallback later stopped on its usage limit. On 2026-09-08 at 11:25 KST, Claude Sonnet 4.6 completed a real 24-turn inference (`is_error: false`) and returned `changes_requested`; its enclosing JSON code fence exposed an adapter parsing issue. The manifest generator rejects empty check lists. Review and verification outcomes are recorded per task in ignored `.harness` evidence; commits require a passing gate. Project-local `.codex` policy files parse as TOML, but native activation from the repository directory is also unverified.
